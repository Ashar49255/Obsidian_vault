## 1 : whats the deal with Proxmox?

- It’s an open-source Virtual Environment with a built-in UI and server.
- You can use a single machine to run multiple OSes at the same time.
- Resize and scale resources as you want.
- Create and destroy as many VMs as you want.
- Play games in one machine, program on another, start a third machine with a Media Center.
- Don’t need to reboot the entire machine to switch to another OS, just start a new VM.

## 2: Complete PXE Boot Sequence

Five phases from power-on to Ubuntu 24.04 autoinstall completion — DHCP, TFTP, iPXE, kernel, and cloud-init.
📡
Phase 1 — DHCP Negotiation
Client broadcasts DHCP Discover on the network
The PXE client powers on and broadcasts a DHCPDISCOVER on UDP port 67. dnsmasq detects the client's firmware type via DHCP option 93 (client-arch) and responds with an IP address plus the appropriate boot filename — `shimx64.efi` for UEFI or `undionly.kpxe` for BIOS.

DHCPDISCOVERDHCPOFFERDHCPREQUESTDHCPACKUDP 67/68

🔀

Phase 1b — Boot Decision Logic

dnsmasq selects the correct boot file for each client type

**If option 175 is set** (iPXE already running): → sends `http://192.168.1.118/boot.ipxe`  
**If arch = 7/9/11** (UEFI x86_64): → sends `shimx64.efi` via TFTP  
**BIOS fallback**: → sends `undionly.kpxe` via TFTP

📦

Phase 2 — TFTP Bootloader Transfer

Client downloads the bootloader from /srv/tftp

The client sends a TFTP Read Request (RRQ) for the assigned boot file. dnsmasq's built-in TFTP server streams the binary in data blocks from /srv/tftp. For UEFI: `shimx64.efi` (Secure Boot shim). For BIOS: `undionly.kpxe` (iPXE stub). Client ACKs each block.

TFTP RRQDATA blocksACKUDP 69

⚡

Phase 3 — iPXE Initialization & Chainloading

iPXE firmware loads and fetches the boot script via HTTP

Once the bootloader executes, iPXE initializes its full network stack and re-sends a DHCP request with **option 175** set. dnsmasq detects this via `dhcp-match=set:ipxe,175` and responds with the HTTP URL for boot.ipxe — this is the iPXE chainloading mechanism that switches from TFTP to HTTP delivery.

DHCP w/ opt175HTTP GET /boot.ipxeTCP 80

🐧

Phase 4 — Kernel & initrd Download

boot.ipxe instructs download of the Ubuntu kernel and ramdisk

The boot.ipxe script executes inside iPXE and issues HTTP GET requests to Apache for the Ubuntu kernel and initial ramdisk from `/var/www/html/casper/`. HTTP is significantly faster than TFTP for large files due to TCP windowing.

GET /casper/vmlinuzGET /casper/initrdTCP 80

🚀

Phase 5 — Ubuntu 24.04 Autoinstall

Kernel boots, cloud-init reads seed data, installation runs unattended

The Linux kernel starts with `ds=nocloud-net` pointing to `http://192.168.1.118/seed/`. cloud-init fetches user-data and meta-data. Subiquity runs fully unattended — LVM partitioning, package install, late-commands (hostname from serial/MAC, GRUB config, deploy SSH key), then auto-reboot.

GET /seed/meta-dataGET /seed/user-dataLVM Installlate-commandsReboot.
