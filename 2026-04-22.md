# 🔄 3. System ka flow (simple story)

Socho:

### Step 1

New server ON hota hai

### Step 2

PXE server usko detect karta hai

### Step 3

Ubuntu automatically install hota hai

### Step 4

Scripts run hoti hain:

- user create
- ZFS encryption setup
- keys generate

### Step 5

Machine ready ho jati hai


The diagram above shows how all components interconnect. Here's what each one does and how they relate:

**FortiClient VPN** is the secure tunnel your engineers use to reach the internal infrastructure from outside. Nothing internal is exposed to the internet — all access goes through VPN first.

**Core Network (Switch/VLAN)** is the backbone. Every server and every client machine connects here. VLANs segment traffic so PXE boot traffic doesn't collide with production traffic.

**PXE Server** is the heart of the system. It runs three services together: DHCP (hands out IP addresses and tells machines where to boot from), TFTP (delivers the iPXE bootloader), and Apache (serves the Ubuntu kernel, initrd, and autoinstall config files).

**Proxmox** is the virtualization host. It runs the PXE Server, GitLab, the Automation Server, and the ZFS Key Server as VMs. You only need one or two physical servers to host your entire infrastructure.

**GitLab CI/CD** stores all your infrastructure code (Ansible playbooks, autoinstall configs, iPXE scripts). When you push a change, a pipeline automatically applies it — no manual SSH-and-edit.

**Automation Server (Ansible + Jenkins + PostgreSQL)** handles post-install tasks. After a machine finishes its OS install, Ansible runs playbooks to configure it (set up users, install packages, apply security hardening). Jenkins orchestrates pipelines. PostgreSQL stores machine records, deployment history, and ZFS key references.

**ZFS Key Server** manages encryption keys for disk encryption on client machines. After OS install, machines request their key to unlock their ZFS pool.
